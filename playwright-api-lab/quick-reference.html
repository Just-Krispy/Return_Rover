5. PowerShell API workflow

GET: read the collection

$items = Invoke-RestMethod -Uri $api -Method Get
$items

POST: create an item

$body = @{
    name = "PowerShell learning item"
    quantity = 7
} | ConvertTo-Json

$created = Invoke-RestMethod `
    -Uri $api `
    -Method Post `
    -ContentType "application/json" `
    -Body $body

$created

GET: retrieve the created item

$itemId = $created.id

$retrieved = Invoke-RestMethod `
    -Uri "$api/$itemId" `
    -Method Get

$retrieved

DELETE: clean up the learning item

Invoke-RestMethod `
    -Uri "$api/$itemId" `
    -Method Delete

PowerShell’s backtick ` means “continue this command on the next line.” It must be the final character on the line—no spaces after it.

7. Playwright API test pattern

import { test, expect } from '@playwright/test';

const apiUrl =
  'https://6a95ddc0fa33b37f821afa85.mockapi.io/lab/v1/name';

test('POST creates an item and GET retrieves it', async ({ request }) => {
  const createResponse = await request.post(apiUrl, {
    data: {
      name: `Playwright item ${Date.now()}`,
      quantity: 7,
    },
  });

  expect(createResponse.status()).toBe(201);

  const createdItem = await createResponse.json();

  const getResponse = await request.get(
    `${apiUrl}/${createdItem.id}`
  );

  expect(getResponse.status()).toBe(200);

  const retrievedItem = await getResponse.json();
  expect(retrievedItem.name).toBe(createdItem.name);
});

request sends HTTP calls. response represents the server response. await waits for the network operation. expect verifies the result.

8. API → UI workflow

  1. Use GET to confirm the API is available.
  2. Use POST to create a uniquely named item.
  3. Use the returned ID in a GET request.
  4. Open your UI and refresh or trigger its data request.
  5. Assert that the item appears in the UI.
  6. Delete the test item during cleanup.

10. Good testing habits

  • Use unique names with Date.now() when tests create records.
  • Assert status codes and important response fields.
  • Clean up created records with DELETE.
  • Keep API tests independent so they can run in parallel.
  • Use Ctrl + S to save before running tests.
  • Use --project=chromium for API-only practice to avoid running the same API test three times.
